Why the notes look like this

The original notes are LaTeX, and they are good LaTeX — careful definitions, worked examples with every step shown, Python snippets that actually run. What a PDF cannot do is let you move anything. A determinant stays a number in a box. An eigenvector stays an arrow in a fixed picture.

So this site keeps the text as it was and rebuilds the figures as things you can grab. The goal is not decoration: it is that you should be able to form a guess, act on it, and be corrected within a second or two. That loop is where intuition comes from, and it is the one thing a static document cannot offer.

The one habit worth forming

Before you drag anything in a playground, say out loud what you expect to happen. If you are right, you understood it. If you are wrong, you have just found the exact gap worth closing — which is far more useful than reading the paragraph again.

On correctness

Every worked example reproduced on this site has been recomputed independently and checked against the original. Where the notes contained a genuine error, the page shows the corrected mathematics and records what changed in the chapter's errata section — openly, rather than quietly.

The interactive figures compute their results numerically at run time rather than displaying pre-rendered answers, so what you see is what the mathematics actually does, including at the awkward edge cases.

How it is built

Plain HTML, CSS and JavaScript — no framework and no build step. Mathematics is typeset with KaTeX. Every interactive figure is a small self-contained module drawing to a <canvas>, sharing one plotting and interaction library. The numerical routines behind them (SVD, eigendecomposition, row reduction) are implemented from scratch so the pages stay dependency-free.

The site is static and hosted on GitHub Pages, which means it loads fast, works offline once cached, and will keep working long after any particular JavaScript framework has gone out of fashion.

Found a mistake?

Please report it. A typo in an exponent can cost a student an hour, and there is no reason for anyone else to lose that hour too. Email mialhajri@aus.edu, or raise it in class or in office hours.

That includes the interactive figures: if a playground behaves oddly, gives a result you cannot reproduce by hand, or is confusing rather than clarifying, that is a bug worth hearing about.
