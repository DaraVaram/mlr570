Part 2.1 · Data Preprocessing

Raw data collected from sensors, databases or user inputs is usually incomplete, noisy, and presented at wildly different scales and formats. Feeding it straight into a model leads to poor performance, biased predictions, or training that simply will not converge.

Preprocessing turns raw data into something a model can actually learn from. Done well, it lets models:

  • learn meaningful patterns efficiently;
  • generalise better to unseen data;
  • converge faster during training, reducing computational cost;
  • avoid problems such as feature dominance and class imbalance.

The components covered here are:

  • Aggregation — combining and summarising data points to reduce complexity and expose higher-level trends, such as turning hourly temperatures into daily averages.
  • Sampling — selecting a representative subset when the full dataset is too large, or rebalancing one that is skewed.
  • Normalisation — rescaling numeric features so they have comparable ranges, preventing income (in thousands) from swamping age (in tens).
  • Encoding — converting categorical variables into numbers without accidentally inventing an ordering that was never there.
  • Discretisation — turning continuous variables into a finite set of bins.
  • Dimensionality reduction and feature selection — cutting the number of features down, either by building new ones or by discarding old ones.
Garbage in, garbage out

The oldest cliché in computing is still the most reliable one. No architecture rescues bad inputs, and high-quality preprocessing routinely makes more difference than a better model.

Why preprocess at all?

Consider a dataset with three well-separated classes and two features, where the first feature happens to be measured on a scale a thousand times larger than the second — say income in dirhams against a satisfaction rating from 1 to 5. Nothing about the structure of the data has changed, only the units. Yet a distance-based method will fall apart.

Aggregation

Aggregation summarises or combines data points to reduce size and complexity — particularly useful for time series and for data that can be viewed at several levels of granularity.

Common techniques.

  • Sum: \(\sum(x_1, \dots, x_n)\).
  • Mean: \(\frac{1}{n}\sum_{i=1}^n x_i\).
  • Median: robust to outliers.
  • Windowed: e.g. a rolling mean over a time window.
  • Spatial: e.g. population density per region.
TechniqueAdvantagesDisadvantages
MeanSimple, efficient for symmetric dataSensitive to outliers
MedianRobust to outliersLoses fine-grained variation
WindowedTracks trends over timeIntroduces lag in real-time systems

Rolling (windowed) aggregation

Definition

Let \(\{x_t\}_{t=1}^T\) be a univariate time series. A rolling aggregation over a fixed window of size \(w\) summarises the last \(w\) observations at each timestamp:

\[ \bar{x}_t = \frac{1}{w}\sum_{i=0}^{w-1} x_{t-i}, \qquad \tilde{x}_t = \operatorname{median}\big(x_{t-w+1}, \dots, x_t\big). \]

Unless stated otherwise the window is right-aligned — it uses only the past, never future samples. This matters: a centred window would leak information from the future, which is catastrophic in forecasting.

What the figure shows:

  • The first \(w-1\) outputs are undefined (NaN), because the window is not yet full. That is a direct consequence of right-alignment.
  • Noise reduction and trend extraction. Averaging over the last \(w\) samples suppresses high-frequency noise and exposes the low-frequency trend. The median does the same with greater robustness.
  • Lag on monotone segments. Because the window only looks backwards, both curves lag the current level on a rising trend and sit above it on a falling one. This is the bias–variance trade-off made visible: larger \(w\) means stronger smoothing (lower variance) but larger lag (higher bias).
  • Outlier sensitivity. The mean has unbounded influence — one extreme value can shift it arbitrarily far. The median has bounded influence and is unaffected by the magnitude of outliers as long as fewer than half the window is corrupted.
Which one in practice?

In noisy sensing or transactional streams where spikes occur — faults, data-entry errors, rare events — a rolling median usually describes local central tendency better. The rolling mean is preferable when outliers are rare and you want the more efficient estimator under Gaussian-like noise.

Weighted windows and the EWMA

A flat window gives each of the last \(w\) samples equal weight. More generally we can weight them:

\[ \bar{x}_t^{(w)} = \frac{\sum_{i=0}^{w-1} \alpha_i\, x_{t-i}}{\sum_{i=0}^{w-1}\alpha_i}, \qquad \alpha_i \ge 0. \]

Choosing \(\alpha_i = \lambda^i\) with \(0 < \lambda < 1\) gives the exponentially weighted moving average, which has a neat recursive form:

\[ \bar{x}_t^{(\lambda)} = (1-\lambda)\,x_t + \lambda\,\bar{x}_{t-1}^{(\lambda)}. \]
  • Recency bias: recent samples count for more.
  • Faster adaptation: reacts to level shifts more quickly than a flat mean.
  • Smoothness parameter: \(\lambda\) is a "forgetting factor" — closer to 1 means slower decay, so smoother but laggier.

Exponential smoothing is widely used in forecasting because it updates online with \(\mathcal{O}(1)\) memory and computation — you never need to store the window at all.

Watch the convention when you reach for a library

Pandas parameterises the EWMA the other way round. Its adjust=False form is \(y_t = \alpha x_t + (1-\alpha) y_{t-1}\), so pandas' \(\alpha\) is our \(1-\lambda\). With span=s it uses \(\alpha = 2/(s+1)\). Same algorithm, mirrored symbol — a very easy way to get smoothing backwards.

Python 
import pandas as pd

# Right-aligned rolling window of size 10 (the default)
df['roll_mean']   = df['y'].rolling(window=10).mean()
df['roll_median'] = df['y'].rolling(window=10).median()

# Exponentially weighted moving average
df['ewm'] = df['y'].ewm(span=10, adjust=False).mean()

# Centred window -- fine for exploratory analysis, NEVER for forecasting
df['centred'] = df['y'].rolling(window=10, center=True).mean()

Choosing the window size

The window \(w\) is a genuine hyperparameter:

  • Small \(w\): preserves short-term fluctuations and reacts quickly, but suppresses less noise.
  • Large \(w\): stronger smoothing and better trend extraction, but more lag and loss of fine temporal detail.
  • Context-dependent: in finance, 5-, 20- and 200-day averages carry entirely different meanings. In environmental studies a 7-day rolling mean removes the day-of-week cycle.

There is no universally optimal \(w\) — it depends on the signal-to-noise ratio, domain convention, and what you intend to do next. The rule of thumb: large enough to suppress noise, small enough not to hide the dynamics you care about.

Sampling

Sampling selects a subset of data from a larger population — to reduce computational cost, to make analysis tractable, or to correct a bias such as class imbalance. A good strategy keeps the subset representative while remaining cheap to work with.

Common techniques

Random sampling. Every data point has an equal chance of selection. Simplest strategy, and it works well for large homogeneous datasets. Example: taking 5,000 tweets at random from a corpus of 5 million for exploratory analysis.

Stratified sampling. Divide the data into strata by some categorical variable and sample proportionally within each, preserving the class proportions. Example: on a medical dataset where 5% of patients have a rare condition, stratified sampling guarantees both the training and validation splits contain 5% positives rather than leaving it to chance.

Oversampling and undersampling. Used for imbalanced classification. Oversampling duplicates or synthesises minority-class samples; undersampling discards majority-class ones. Example: in fraud detection where 0.1% of transactions are fraudulent, SMOTE can synthesise minority samples while undersampling keeps the dataset manageable.

Systematic sampling. Take every \(k^{\text{th}}\) point from an ordered dataset after a random start. Simple and evenly spread, but it goes badly wrong if the data has a period that resonates with \(k\). Example: quality control on every 100th item off an assembly line.

Oversampling is not free

Synthesising minority-class samples means inventing data that was never observed. Where each tends to apply:

  • Image datasets: stratified sampling keeps each object class proportional across train, validation and test.
  • Surveys: pollsters stratify by demographics — age, gender, region.
  • Streaming data: systematic sampling suits sensor monitoring, e.g. every 10th reading from an IoT device.
  • Imbalanced tabular data: over- or undersampling to make learning feasible.

Further reading · advanced strategies

  • Importance sampling: draw with probability proportional to a point's importance for the estimate. Central to Monte Carlo methods, reinforcement learning and Bayesian inference.
  • Cluster sampling: sample whole groups rather than individuals — common in survey statistics when the population is geographically distributed.
  • Reservoir sampling: obtain a uniform random sample from a stream of unknown length in one pass, with fixed memory.
  • Adaptive sampling: let the strategy respond to intermediate results, concentrating effort on informative regions — the idea behind active learning.
  • Synthetic data generation: rather than duplicating minority samples, generate new ones with SMOTE or a GAN.

Normalisation

Normalisation rescales features to comparable ranges so that those with larger magnitudes do not dominate learning. It is critical for distance-based models (k-NN, SVMs, k-means) and for gradient-based optimisers, where feature scale directly affects how fast — and whether — training converges.

Definition

Min–max normalisation rescales each feature into a fixed interval, usually \([0,1]\):

\[ x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}} \]

Z-score normalisation (standardisation) centres to mean 0 and unit variance:

\[ x' = \frac{x - \mu_x}{\sigma_x} \]

Robust scaling replaces the mean and standard deviation with the median and interquartile range, so outliers stop dictating the transformation:

\[ x' = \frac{x - \operatorname{median}(x)}{\mathrm{IQR}(x)} \]

Real-world examples

  • Image data (0–255 pixel values): min–max into \([0,1]\) improves numerical stability in neural networks.
  • Financial data: stock returns take both signs, so z-score normalisation makes stocks of different volatilities comparable.
  • Sensor data: temperature, humidity and pressure need rescaling so no single measurement dominates a clustering.
Fit on training data only — this is a real source of data leakage

Always fit the scaler on the training set and apply that same transformation to validation and test data. Fitting on the whole dataset lets the test set's minimum, maximum or mean influence the training inputs, which leaks information and produces optimistic results that evaporate in deployment. In scikit-learn: fit_transform on train, transform on everything else.

Python 
from sklearn.preprocessing import MinMaxScaler, StandardScaler, RobustScaler

scaler = StandardScaler()
X_train_s = scaler.fit_transform(X_train)   # fit AND transform on train
X_test_s  = scaler.transform(X_test)        # transform only -- never re-fit

# Safer still: put it in a pipeline so leakage becomes impossible
from sklearn.pipeline import make_pipeline
from sklearn.svm import SVC
model = make_pipeline(StandardScaler(), SVC())
model.fit(X_train, y_train)

Further reading · advanced techniques

  • Log and power transforms: reduce skewness and stabilise variance for heavy-tailed distributions.
  • Unit vector (\(\ell_2\)) normalisation: rescale each sample to unit norm — standard in text processing with TF–IDF.
  • Batch and layer normalisation: neural-network methods that normalise activations rather than raw features, to stabilise training.
  • Whitening: transform correlated features into uncorrelated ones with unit variance, e.g. PCA whitening.

Encoding

Most models require numeric input, so categorical features must be converted. The scheme you choose affects both interpretability and performance — and one of them quietly introduces a falsehood.

One column, four encodings

Add categories and watch one-hot grow linearly while binary grows logarithmically — and see exactly what false ordering label encoding introduces.

Play

Label encoding

Assign each category a unique integer:

\[ \{\text{Red}, \text{Green}, \text{Blue}\} \;\longrightarrow\; \{0, 1, 2\} \]
The invented ordering

Mapping to 0, 1, 2 tells any model that reads numeric magnitude that Blue > Green > Red, and that Red is twice as far from Blue as from Green. Neither statement is true. This actively misleads linear models and distance-based methods. It is harmless for tree-based models, which only ever compare thresholds — which is why label encoding survives at all.

One-hot encoding

Create one binary column per category, with a 1 where the category is present:

ColourRedGreenBlue
Red100
Green010
Blue001
Red100

No false ordering, and every pair of categories is equidistant. Works well for low-cardinality nominal variables. The limitation is width: thousands of categories produce a very sparse, very high-dimensional matrix.

Frequency encoding

Replace each category with how often it occurs. With fruits Apple ×3, Banana ×1, Orange ×1:

\[ [\text{Apple}, \text{Banana}, \text{Apple}, \text{Orange}, \text{Apple}] \;\longrightarrow\; [3, 1, 3, 1, 3] \]

One column regardless of cardinality, which is attractive for high-cardinality features. But it assumes frequency carries information about the target — often false — and it makes two equally common categories indistinguishable: Banana and Orange both become 1.

Binary encoding

Map categories to integers, then write those integers in binary and split the bits into columns:

CategoryIntegerBinary
A1001
B2010
C3011
D4100

This needs \(\lceil \log_2(k+1) \rceil\) columns for \(k\) categories instead of one-hot's \(k\) — a dramatic saving at high cardinality. The cost is interpretability: an individual bit column means nothing on its own.

Python 
import pandas as pd
from sklearn.preprocessing import LabelEncoder

df = pd.DataFrame({'Color': ['Red', 'Green', 'Blue', 'Red']})

# Label encoding
df['LabelEnc'] = LabelEncoder().fit_transform(df['Color'])

# One-hot encoding
df_onehot = pd.get_dummies(df, columns=['Color'])

# Frequency encoding
df['FreqEnc'] = df['Color'].map(df['Color'].value_counts())

# Binary encoding (pip install category_encoders)
import category_encoders as ce
df_binary = ce.BinaryEncoder(cols=['Color']).fit_transform(df['Color'])

Real-world examples

  • Retail: encoding product categories for a recommendation system.
  • NLP: encoding tokens before they reach an embedding layer — one-hot into a dense embedding.
  • Healthcare: encoding diagnosis codes, which are extremely high-cardinality.
  • Web analytics: encoding device types, browsers, regions.

Discretisation

Discretisation converts continuous variables into discrete bins. It is useful when you want to:

  • use models that expect categorical input (e.g. Naïve Bayes);
  • reduce sensitivity to small variations and noise;
  • make outputs more interpretable — grouping ages into "20–29", "30–39".

Three ways to cut the same ten scores

Equal width, equal frequency, and k-means — with the bin edges, counts and within-bin variance computed live.

Play

Equal-width binning

Divide the range into \(k\) intervals of identical width:

\[ \text{bin}(x) = \left\lfloor \frac{x - \min(x)}{\big(\max(x)-\min(x)\big)/k} \right\rfloor \]
Example

Ten exam scores \(\{15, 22, 35, 41, 46, 53, 67, 72, 85, 93\}\), with \(\min = 15\), \(\max = 93\) and \(k = 4\). Each bin has width \((93-15)/4 = 19.5\).

BinIntervalScoresCount
1[15, 34.5)15, 222
2[34.5, 54)35, 41, 46, 534
3[54, 73.5)67, 722
4[73.5, 93]85, 932

The bins are evenly spaced but the counts are not: 2, 4, 2, 2. That unevenness is the defining characteristic of equal-width binning — and on skewed data it gets much worse, with most points crowding into one bin and others left nearly empty.

Equal-frequency binning

Also called quantile binning: sort the values and place approximately the same number of samples in each bin, whatever that does to the widths.

"Approximately" is doing real work in that sentence

With 10 points and 4 bins, exactly equal counts are arithmetically impossible — 10 does not divide by 4. Equal-frequency binning can only balance the counts as evenly as the arithmetic allows, here 3, 2, 2, 3. Ties make it worse still: if many points share a value they cannot be split across bins, and pd.qcut will raise an error or silently produce fewer bins than you asked for.

Applying pd.qcut with \(k = 4\) to the same scores gives quartile edges at 36.5, 49.5 and 70.75, producing bins of 3, 2, 2 and 3 scores. Bin 1 spans \([15, 36.5]\) — a width of 21.5 — while bin 2 spans just \((36.5, 49.5]\), a width of 13. Balanced counts, unbalanced widths: exactly the opposite trade-off from equal-width binning.

K-means binning

Rather than fixing widths or counts, partition the values into \(k\) clusters that minimise the within-cluster variance. The bin assignments are then the cluster memberships.

Example

For the same ten scores with \(k = 3\), k-means converges to:

ClusterScoresCentroid
115, 2218.50
235, 41, 46, 5343.75
367, 72, 85, 9379.25

Total within-cluster sum of squares: 624.0. You can confirm this is a fixed point of Lloyd's algorithm — the midpoint between centroids 18.5 and 43.75 is 31.1, and between 43.75 and 79.25 is 61.5, so reassigning each score to its nearest centroid reproduces exactly these three groups.

Notice the cuts land in the two largest gaps in the data — between 22 and 35, and between 53 and 67. That is the whole appeal: k-means puts boundaries where the data is already sparse rather than at arbitrary round numbers.

import pandas as pd
from sklearn.preprocessing import KBinsDiscretizer

scores = pd.DataFrame({'score': [15, 22, 35, 41, 46, 53, 67, 72, 85, 93]})

# k-means binning

  • Healthcare: age discretised into bands for epidemiological studies.
  • Finance: credit scores or income grouped into risk bands.
  • Retail: purchase amounts grouped into basket sizes.
  • Data compression: continuous signals quantised into fewer levels.

Dimensionality reduction

Dimensionality reduction maps high-dimensional data into a lower-dimensional space. It helps with:

  • Efficiency: lower computation and storage cost.
  • Noise reduction: suppressing uninformative variation.
  • Visualisation: making high-dimensional data legible in 2-D or 3-D.
  • Generalisation: reducing overfitting by discarding redundant features.

Common techniques include:

  • PCA — linear projection maximising variance.
  • LDA — supervised projection maximising class separation.
  • t-SNE — non-linear embedding, for visualisation.
  • UMAP — manifold-based embedding, efficient at scale.
  • Random projection — a simple linear projection with the Johnson–Lindenstrauss guarantee.

This course covers PCA and feature selection. The others are left as further reading.

Principal component analysis

Definition

PCA finds a new set of orthogonal axes — the principal components — such that the projected data retains as much variance as possible. Given \(\mathbf{X} \in \mathbb{R}^{n \times d}\) with \(n\) samples and \(d\) features, PCA finds \(k < d\) orthogonal directions \(\mathbf{W}_k \in \mathbb{R}^{d \times k}\) so that \(\mathbf{Y} = \mathbf{X}_c\mathbf{W}_k\) has maximum variance.

The procedure:

  1. Centre: subtract each feature's mean, \(\mathbf{X}_c = \mathbf{X} - \mu\).
  2. Covariance: compute \(\Sigma = \frac{1}{n-1}\mathbf{X}_c^T\mathbf{X}_c \in \mathbb{R}^{d\times d}\).
  3. Eigendecomposition: solve \(\Sigma v_i = \lambda_i v_i\). Each \(v_i\) is a principal component and \(\lambda_i\) the variance along it.
  4. Project: take the top-\(k\) eigenvectors by eigenvalue to form \(\mathbf{W}_k\) and compute \(\mathbf{Y} = \mathbf{X}_c\mathbf{W}_k\).

Via the SVD

Rather than forming the covariance matrix explicitly, PCA is usually computed from the SVD of the centred data:

\[ \mathbf{X}_c = \mathbf{U}\mathbf{S}\mathbf{V}^T, \]

where the columns of \(\mathbf{V}\) are the principal components. This is numerically more stable — forming \(\mathbf{X}_c^T\mathbf{X}_c\) squares the condition number, so small singular values get lost to rounding. The relationship to the eigenvalues is \(\lambda_i = \sigma_i^2/(n-1)\), which connects directly back to Chapter 1's SVD.

Two equivalent views

  • Variance maximisation: \[ \max_{\mathbf{W} \in \mathbb{R}^{d\times k}} \operatorname{tr}(\mathbf{W}^T\Sigma\mathbf{W}) \quad \text{s.t. } \mathbf{W}^T\mathbf{W} = \mathbf{I}. \]
  • Reconstruction error minimisation: \[ \min_{\mathbf{W} \in \mathbb{R}^{d\times k}} \lVert \mathbf{X}_c - \mathbf{X}_c\mathbf{W}\mathbf{W}^T \rVert_F^2. \]

These give the same answer. Keeping the directions of greatest spread is the same thing as discarding the directions you can most afford to lose — which is exactly the Eckart–Young statement from Chapter 1, seen from the other side.

Explained variance and choosing \(k\)

Each eigenvalue is the variance captured by its component:

\[ \text{explained variance ratio}_i = \frac{\lambda_i}{\sum_j \lambda_j}. \]

Common heuristics for choosing \(k\):

  • Elbow method: plot the explained variance per component and look for the point where it flattens.
  • Variance threshold: keep enough components to reach, say, 95% of the total.
  • Cross-validation: pick the \(k\) that performs best on the downstream task — the only criterion that is really about your problem.

The scree plot — and why standardisation changes everything

Toggle standardisation and watch the explained-variance split transform. On raw data PC1 looks dominant; that is units talking, not structure.

Play
Standardise first, or PCA will just find your largest unit

PCA maximises variance, and variance is not unit-free. Measure a length in millimetres instead of metres and its variance grows by \(10^6\) — so it will dominate PC1 regardless of whether it carries any real information. On a dataset mixing income in thousands with age in tens, an unstandardised PCA will report that PC1 explains almost everything. That number is describing the income column's units.

The one legitimate exception is when all features are already in the same units and their relative scales are meaningful — pixel intensities, or all-in-dirhams financial columns. Otherwise, standardise.

Geometric interpretation

  • The first principal component is the direction of maximum variance in feature space.
  • The second is orthogonal to the first and captures the next most, and so on.
  • PCA rotates the coordinate system to align with the directions the data actually spreads in.

Limitations

  • Linear only: PCA captures linear correlations. Data on a curved manifold needs Kernel PCA, t-SNE or UMAP.
  • Interpretability: components are linear combinations of all original features, so "PC1" rarely has a clean meaning.
  • Outlier sensitivity: variance is dominated by extreme points, which can drag a component onto a handful of samples.
  • Scale dependence: as above — results change entirely with the units unless you standardise.
  • Unsupervised: PCA never looks at the labels, so the direction of greatest variance may not be the direction that separates your classes. LDA is the supervised alternative.
Python 
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

# Standardise, then reduce -- in a pipeline so the scaler is fitted on train only
pipe = make_pipeline(StandardScaler(), PCA(n_components=2))
X_pca = pipe.fit_transform(X_train)

pca = pipe.named_steps['pca']
print("explained variance ratio:", pca.explained_variance_ratio_)
print("cumulative:", pca.explained_variance_ratio_.cumsum())

# How many components to reach 95% of the variance?
full = PCA().fit(StandardScaler().fit_transform(X_train))
import numpy as np
k95 = np.searchsorted(full.explained_variance_ratio_.cumsum(), 0.95) + 1

Applications

  • Image compression: reduce pixel intensities to a few components.
  • Finance: extract the market factors driving correlated returns.
  • Genomics: summarise genetic variation across populations.
  • NLP: reduce word-embedding dimensionality before clustering.
  • Visualisation: plot high-dimensional embeddings in 2-D or 3-D.

Feature selection

Feature selection identifies the most relevant subset of the original features. This is the key difference from dimensionality reduction: PCA builds new synthetic features, while feature selection keeps a subset of the ones you started with — so the survivors are still interpretable, still named, and still measurable in the real world.

Motivations:

  • Generalisation: removing irrelevant or noisy features reduces variance and overfitting.
  • Efficiency: smaller feature sets train and infer faster.
  • Interpretability: the selected features are direct insight into the problem — and if a feature is expensive to collect, dropping it saves real money.

Methods fall into three families: filter, wrapper and embedded.

Filter methods

Filter methods score features by a statistical criterion, independently of any model. They are fast, interpretable, and usually applied as a first pass.

  • Variance threshold: drop features that barely vary. \[ \operatorname{Var}(\mathbf{X}_j) = \frac{1}{n}\sum_{i=1}^n (\mathbf{X}_{ij} - \mu_j)^2 \] Note this never looks at the target, so it can only tell you a feature is constant, never that it is useful.
  • Correlation coefficient: measures linear association with the target. \[ \rho(\mathbf{X}_j, y) = \frac{\operatorname{Cov}(\mathbf{X}_j, y)}{\sigma_{\mathbf{X}_j}\sigma_y}, \qquad -1 \le \rho \le 1 \]
  • Mutual information: the reduction in uncertainty about \(y\) given \(\mathbf{X}_j\), capturing linear and non-linear dependence. \[ I(\mathbf{X}_j; y) = \sum_{x,y} p(x,y)\log\frac{p(x,y)}{p(x)p(y)} \]

Three criteria, three different answers

Pros: simple, fast, scalable to very high dimensions, model-independent.

Cons: ignores feature interactions, and happily selects redundant features — two columns that both correlate with the target will both score highly even if one is a copy of the other.

Wrapper methods

Wrapper methods evaluate feature subsets by actually training a model on them. This captures interactions and redundancy that filters miss, at considerable computational cost.

  • Recursive feature elimination (RFE): train on all features, rank them by importance, drop the weakest, and repeat until the desired number remains.
  • Forward selection: start empty and repeatedly add whichever feature most improves cross-validated performance.
  • Backward elimination: start with everything and repeatedly remove the least useful.

Pros: accounts for interactions; tailored to the model you will actually use.

Cons: expensive — evaluating all subsets of \(d\) features is \(2^d\) model fits, so these are greedy approximations. Prone to overfitting the selection itself unless the search is wrapped in cross-validation.

Embedded methods

Embedded methods fold feature selection into training itself, by penalising the model for relying on too many features.

  • Lasso (\(\ell_1\) regularisation): adds a penalty proportional to the absolute value of the coefficients, \[ \min_\mathbf{w} \frac{1}{2n}\lVert \mathbf{X}\mathbf{w} - \mathbf{y}\rVert_2^2 + \lambda\lVert \mathbf{w}\rVert_1. \] Larger \(\lambda\) shrinks coefficients, driving some to exactly zero — that is feature elimination as a side effect of fitting. The reason \(\ell_1\) does this and \(\ell_2\) does not is the diamond-shaped unit ball with corners on the axes, which you can see in Chapter 1's norms figure.
  • Trees and ensembles: random forests and gradient-boosted trees rank features by impurity decrease as a by-product of training.
  • Elastic net: combines \(\ell_1\) sparsity with \(\ell_2\) stability, \[ \min_\mathbf{w} \frac{1}{2n}\lVert \mathbf{X}\mathbf{w} - \mathbf{y}\rVert_2^2 + \alpha\big(\lambda_1\lVert\mathbf{w}\rVert_1 + \lambda_2\lVert\mathbf{w}\rVert_2^2\big), \] which behaves better than plain Lasso when features are strongly correlated.

Pros: far cheaper than wrappers, considers interactions, integrated with training.

Cons: model-dependent — the selection reflects what that particular regulariser favours.

Practical considerations
  • Redundancy: strongly correlated features all look important individually. Check a correlation matrix and drop duplicates before trusting any filter ranking.
  • Selection is part of the model: if you pick features using the whole dataset and then cross-validate, you have already leaked. Feature selection belongs inside the cross-validation loop.
  • Scalability: for genomics or text, start with filters; wrappers are infeasible at \(d = 10^5\).
  • Hybrid: filter aggressively first, then apply a wrapper or embedded method to the survivors.

Part 2.2 · Similarity Measures

A great deal of machine learning reduces to one question: how alike are these two things? Clustering groups points that are similar; k-NN classifies by looking at nearby examples; recommenders find users with similar taste; retrieval finds documents close to a query. Each of those needs a number that quantifies similarity — and the number you choose changes the answer.

This part covers the five measures used in this course:

  • Pearson correlation
  • Euclidean distance
  • Manhattan distance
  • Cosine similarity
  • Jaccard similarity

This is not an exhaustive list — Mahalanobis, Hamming, edit distance, earth mover's distance and many others exist, and are worth exploring if your data calls for them.

Similarity, distance, and what makes a metric

Similarity is large when things are alike; distance is small. They are usually convertible, but not always cleanly.

A distance \(d\) is a true metric when it satisfies four conditions: \(d(a,b) \ge 0\); \(d(a,b) = 0\) exactly when \(a = b\); symmetry \(d(a,b) = d(b,a)\); and the triangle inequality \(d(a,c) \le d(a,b) + d(b,c)\). That last one is what lets algorithms prune search space safely, so it is a practical property and not just a formality. Euclidean and Manhattan distances are metrics. Cosine distance is not.

Pearson correlation

Definition

The Pearson correlation coefficient measures the linear relationship between two variables:

\[ \rho_{A,B} = \frac{\operatorname{cov}(A,B)}{\sigma_A \sigma_B} \]

It is bounded in \([-1, 1]\), and it is scale-invariant — multiplying either variable by a positive constant leaves \(\rho\) unchanged.

The word "linear" is the whole warning

Pearson can only see straight-line association. If your data is related non-linearly, \(\rho\) may be exactly zero while the relationship is perfect and deterministic. A correlation of 0 means "no linear relationship", never "no relationship".

Where correlation succeeds, and where it lies

Example · a perfect linear relationship

Let \(A = [1,2,3,4,5]\) and \(B = [2,4,6,8,10]\), so \(B = 2A\). Using the population convention (dividing by \(n\)):

  1. \(\bar{A} = 3\), \(\bar{B} = 6\).
  2. \(\operatorname{Cov}(A,B) = \frac{1}{5}\sum(A_i - \bar{A})(B_i - \bar{B}) = \frac{1}{5}(8 + 2 + 0 + 2 + 8) = 4\).
  3. \(\sigma_A = \sqrt{\frac{1}{5}(4+1+0+1+4)} = \sqrt{2}\), \quad \(\sigma_B = \sqrt{\frac{1}{5}(16+4+0+4+16)} = \sqrt{8}\).
  4. \(\rho_{A,B} = \dfrac{4}{\sqrt{2}\cdot\sqrt{8}} = \dfrac{4}{4} = 1\).

Note that \(\rho = 1\) tells you the points lie exactly on a straight line — it says nothing about the slope. \(B = 2A\) and \(B = 100A\) both give \(\rho = 1\).

Example · a perfect non-linear relationship

Now let \(A = [-5, -4, \dots, 4, 5]\) and \(B = A^2 = [25, 16, 9, 4, 1, 0, 1, 4, 9, 16, 25]\). Here \(n = 11\).

  • \(\bar{A} = 0\) by symmetry, and \(\bar{B} = \frac{110}{11} = 10\).
  • \(\operatorname{Cov}(A,B) = \frac{1}{11}\sum (A_i - 0)(B_i - 10) = \frac{1}{11}\sum A_i^3 = 0\), because the cubes cancel in pairs: \((-5)^3 + 5^3 = 0\), and so on.
  • Therefore \(\rho_{A,B} = 0\).

\(B\) is a perfect, deterministic function of \(A\) — and Pearson reports no relationship whatsoever. Every point on the left of the parabola contributes a negative product, every point on the right contributes an equal positive one, and they cancel exactly. Load the "Parabola" preset above to watch the violet and red points balance out.

Applications. Feature selection (dropping features highly correlated with one another), and analysing relationships in regression.

Limitations. Blind to non-linear relationships, and sensitive to outliers — as the "One outlier" preset shows, a single point can create the appearance of correlation where none exists. When you suspect either problem, Spearman's rank correlation is a useful companion: it correlates the ranks rather than the values, so it detects any monotonic relationship and shrugs off outliers. It still returns 0 on the symmetric parabola, because that relationship is not monotonic either.

Euclidean and Manhattan distance

Definition

Euclidean (\(\ell_2\)) — the straight-line distance between two points in \(\mathbb{R}^n\):

\[ d(A,B) = \sqrt{\sum_{i=1}^n (A_i - B_i)^2} \]

Manhattan (\(\ell_1\)) — distance measured along axes at right angles:

\[ d(A,B) = \sum_{i=1}^n |A_i - B_i| \]

Both are special cases of the Minkowski distance \(d_p(A,B) = \big(\sum_i |A_i - B_i|^p\big)^{1/p}\), with \(p = 2\) and \(p = 1\) respectively. Taking \(p \to \infty\) gives the Chebyshev distance \(\max_i |A_i - B_i|\).

Example

With \(A = [1,2,3]\) and \(B = [4,5,6]\), each coordinate differs by 3:

\[ d_{\text{Euclidean}} = \sqrt{(-3)^2 + (-3)^2 + (-3)^2} = \sqrt{27} \approx 5.196 \] \[ d_{\text{Manhattan}} = |{-3}| + |{-3}| + |{-3}| = 9 \]

The Manhattan distance is larger, as it always is when more than one coordinate differs — the straight line is a shortcut past the staircase.

Interpretation.

  • Euclidean: "as the crow flies". The natural choice when movement in any direction is equally possible.
  • Manhattan: movement restricted to the axes, like navigating a city grid — appropriate whenever diagonal movement is impossible or meaningless.

Applications. Euclidean distance underpins k-NN classification and k-means clustering. Manhattan distance suits grid pathfinding, image processing, and settings where features should be treated independently.

When Manhattan is preferable.

  • More robust to outliers. Euclidean distance squares each coordinate difference, so a single wildly-wrong dimension dominates. Manhattan grows only linearly with that difference.
  • More stable in high dimensions. Distances concentrate as dimension grows — the subject of the next section — and lower-order norms concentrate more slowly, so \(\ell_1\) retains discriminative power a little longer than \(\ell_2\).
Both are wrecked by unscaled features

Every distance in this section adds contributions across features, so any feature with a large numeric range dominates the sum. Return to the normalisation figure if this needs reinforcing — it is the single most common way distance-based methods fail silently.

The curse of dimensionality

Distance-based methods rest on an assumption that is easy to overlook: that "near" and "far" are meaningfully different. In high dimensions, that assumption quietly fails.

Take a random query point, draw a cloud of random points around it, and compute the ratio of the nearest distance to the farthest. If that ratio is small, the nearest neighbour is genuinely distinctive. If it approaches 1, everything is about equally far away and the nearest neighbour is no longer meaningfully nearer than anything else.

What the figure shows:

  1. Low dimensions (2–10). The ratio is small. The nearest neighbour is much closer than the farthest, so distances carry real information and k-NN or k-means behave sensibly.
  2. High dimensions (100–1000). The ratio climbs steadily toward 1. Nearest and farthest neighbours sit at almost the same distance — intuitively, everything looks equally far.
  3. Euclidean versus Manhattan. Both converge toward 1, but Euclidean concentrates slightly faster. This reflects how they scale with dimension: for random points, expected Euclidean distance grows like \(\sqrt{d}\) while the spread of distances grows more slowly, so the relative contrast shrinks.
Why this matters

This is the concrete reason distance-based methods degrade on high-dimensional data, and the reason dimensionality reduction and feature selection are not merely efficiency tricks — they are often what makes the method work at all. It is also why cosine similarity is preferred for high-dimensional embeddings: by discarding magnitude and keeping only angle, it sidesteps some of this concentration.

Cosine similarity

Definition

Cosine similarity is the cosine of the angle between two vectors:

\[ \text{cosine}(A,B) = \frac{A \cdot B}{\lVert A\rVert\,\lVert B\rVert} \]

It ranges over \([-1, 1]\) in general, and over \([0, 1]\) when all components are non-negative — as they are for word counts, TF–IDF vectors and most feature histograms.

Examples

1. With \(A = [1,2,3]\) and \(B = [4,5,6]\):

\[ A \cdot B = 4 + 10 + 18 = 32, \qquad \lVert A\rVert = \sqrt{14}, \qquad \lVert B\rVert = \sqrt{77} \] \[ \text{cosine}(A,B) = \frac{32}{\sqrt{14}\sqrt{77}} = \frac{32}{\sqrt{1078}} \approx 0.9746 \]

2 · perfect alignment. With \(A = [1,2,3]\) and \(C = [2,4,6] = 2A\):

\[ \text{cosine}(A,C) = 1 \]

The vectors point in exactly the same direction, so the angle is zero, whatever their lengths. Note the contrast: the Euclidean distance between \(A\) and \(C\) is \(\sqrt{1+4+9} = \sqrt{14} \approx 3.74\), which is not small at all.

Applications.

  • Document similarity: bag-of-words and TF–IDF vectors, where document length varies wildly.
  • Recommender systems: comparing users by rating patterns rather than by how much they rate.
  • Embeddings: word2vec, sentence and image embeddings — the default similarity in modern retrieval and RAG systems.

Advantages. Captures orientation regardless of magnitude, which makes it robust to differences in scale and to the length of documents. It also behaves better than raw Euclidean distance in the high-dimensional sparse settings where text lives.

On "cosine is not a true metric"

Worth stating precisely, because it is easy to garble. Cosine similarity is not a distance at all — it gets larger as things become more alike, so the metric axioms do not even apply to it.

The derived cosine distance \(1 - \cos\theta\) is a distance, and it genuinely fails the triangle inequality. But the angular distance \(\theta = \arccos(\cos\theta)\) is a proper metric. So the honest statement is: cosine distance is not a metric, though a metric closely related to it exists.

Limitation. Cosine similarity discards magnitude entirely. If magnitude carries information — total spend, signal strength, how many times a user actually watched something — that information is thrown away. Two customers who buy the same products in a 1:2:3 ratio look identical even if one spends a hundred times more.

Jaccard similarity

Definition

Jaccard similarity measures the overlap between two sets:

\[ J(A,B) = \frac{|A \cap B|}{|A \cup B|} \]

It ranges from 0 (disjoint) to 1 (identical). The complement \(1 - J(A,B)\) is the Jaccard distance, which — unlike cosine distance — is a true metric.

1 · sets. \(A = \{1,2,3,4,5\}\), \(B = \{4,5,6,7\}\):

\[ A \cap B = \{4,5\}, \qquad A \cup B = \{1,2,3,4,5,6,7\} \] \[ J(A,B) = \frac{2}{7} \approx 0.286 \]

  • Doc1 = {machine, learning, is, amazing}
  • Doc2 = {deep, learning, is, amazing}

The intersection is {learning, is, amazing} and the union has 5 distinct words, so \(J = \frac{3}{5} = 0.6\).

3 · binary vectors. \(A = [1,0,1,0,1]\), \(B = [1,1,0,0,1]\). Treating each as the set of positions holding a 1, \(A = \{1,3,5\}\) and \(B = \{1,2,5\}\):

\[ J = \frac{|\{1,5\}|}{|\{1,2,3,5\}|} = \frac{2}{4} = 0.5 \]

Note that position 4 is 0 in both vectors and contributes to neither the intersection nor the union. Jaccard deliberately ignores joint absences — which is the right behaviour for sparse data, where almost everything is absent from almost everything.

Applications. Document similarity in text mining, clustering categorical data, comparing binary feature vectors, near-duplicate detection (via MinHash), and measuring overlap between user or tag sets.

Advantages. Robust to document length, intuitive, and naturally suited to set-valued data where no numeric magnitude exists.

Limitation. It ignores frequency entirely: a document mentioning "learning" fifty times and one mentioning it once are treated identically. When counts matter, use cosine similarity over count vectors instead.

How to choose

Ask what "similar" is supposed to mean for your data. If magnitude is meaningful, use a distance. If only proportion or direction matters, use cosine. If the data is set-valued or binary, use Jaccard. If you care whether two variables move together rather than whether they are close, use correlation. And whichever you pick, scale your features first unless the measure is explicitly scale-invariant.

Part 2.3 · Model Evaluation

Building a model is the easy part. Knowing whether it works — honestly, on data it has never seen, measured by something that reflects what you actually care about — is where most of the difficulty lives.

Training, validation and testing

Model development requires the dataset to be separated into distinct subsets:

  • Training set. Used to fit the model's parameters by minimising the training error. This is what the model actually learns patterns from.
  • Validation set. Used for hyperparameter tuning and monitoring. The validation error estimates how well the model generalises beyond what it was trained on, and is what you use to make choices.
  • Test set. Used once, after all training and selection is complete, to give an unbiased estimate of final performance.

A typical split of 1000 samples is 70% (700) for training, 15% (150) for validation and 15% (150) for testing. There is a genuine balance to strike: more training data means the model learns more, but leaves less to evaluate it with, and a performance estimate from 50 samples is close to worthless.

The test set is not a validation set you check more often

Every time you look at test performance and then change something — a hyperparameter, a feature, an architecture — you have used the test set to make a decision, and it has stopped being an unbiased estimate. Do that twenty times and your reported test score is optimistic by a margin you cannot measure. This is one of the most common and least visible failures in applied machine learning.

Over- and under-fitting

Definition

Under-fitting. The model is too simple to capture the structure in the data, so both training and test error are high. Causes: a model that is not expressive enough for the problem, or one that simply has not been trained long enough.

Over-fitting. The model is too complex and has captured noise in the training data, so training error is low while validation and test error are high. Causes: an over-parameterised model, too little data, or training for too long.

K-fold cross-validation

A single train/validation split has a problem: the estimate depends on which points happened to land in the validation set. With limited data, an unlucky split can mislead you badly. K-fold cross-validation removes that dependence.

Definition

Split the data into \(K\) folds. Train the model \(K\) times:

  • each time, use \(K-1\) folds for training and the remaining fold for validation;
  • rotate which fold is held out.

The reported performance is the average across all \(K\) folds.

The validation block rotates

Step through the rounds one at a time. Every point trains in K−1 rounds and validates in exactly one.

Play

Advantages.

  • More reliable estimates — every point contributes to both training and validation.
  • Reduces the risk of being fooled by one unlucky split, though it does not eliminate over-fitting.
  • Especially valuable when the dataset is small, where holding out 15% would be painful.
  • The spread across folds is itself informative: consistent scores suggest genuine generalisation, wildly varying ones suggest instability.

The trade-off is cost and fold size. More folds means each model trains on more data (lower bias) but each validation set is smaller, making the per-fold estimates noisier — and you pay \(K\) training runs. \(K = 5\) or \(K = 10\) is the usual compromise. Taking \(K = n\) gives leave-one-out cross-validation, which uses the maximum training data but is expensive and can have high variance.

Stratify, and mind the leakage

For classification, use stratified folds so each fold preserves the class balance — otherwise a rare class may be absent from some folds entirely. And remember that any preprocessing fitted on data (scalers, feature selection, imputation) must be fitted inside each fold, not once beforehand. Use a scikit-learn Pipeline and this becomes automatic.

Python 
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

# The scaler is re-fitted inside every fold -- no leakage
pipe = make_pipeline(StandardScaler(), SVC())
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

scores = cross_val_score(pipe, X, y, cv=cv, scoring='f1_macro')
print(f"{scores.mean():.3f} +/- {scores.std():.3f}")

Accuracy

\[ \text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN} \]

The fraction of predictions that are correct. Intuitive, and badly misleading on imbalanced data — as the sampling figure showed, a model that always predicts the majority class scores 90% on a 90/10 split while being useless.

Precision

\[ \text{Precision} = \frac{TP}{TP + FP} \]

Of everything the model flagged as positive, what fraction really was? High precision means false alarms are rare. This is what you optimise when acting on a positive prediction is costly: flagging a legitimate email as spam, or an unnecessary surgical intervention.

Recall (sensitivity)

\[ \text{Recall} = \frac{TP}{TP + FN} \]

Of everything that actually was positive, what fraction did the model catch? High recall means few misses. This is what you optimise when missing a positive is costly: screening for a treatable disease, or detecting fraud.

Remembering which is which

Both have \(TP\) on top; only the denominator differs. Precision divides by everything you predicted positive — it reads down the predicted-positive column. Recall divides by everything that was positive — it reads across the actual-positive row. Precision is about the quality of your alarms; recall is about your coverage.

F₁ score

\[ F_1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} \]

The harmonic mean of precision and recall, which penalises a large imbalance between the two.

Why the harmonic mean?

Because it refuses to be fooled by one good number. Take a model with Precision = 0.1 and Recall = 0.9:

MeanFormulaValueVerdict
Arithmetic \(\frac{P + R}{2}\) \(\frac{0.1 + 0.9}{2} = 0.50\) Suggests balanced performance — badly misleading
Geometric \(\sqrt{P \cdot R}\) \(\sqrt{0.09} = 0.30\) Better, but still does not punish the 0.1 enough
Harmonic \(\frac{2PR}{P+R}\) \(\frac{0.18}{1.0} = 0.18\) Correctly reflects that the model is poor

It always holds that

\[ \text{harmonic mean} \;\le\; \text{geometric mean} \;\le\; \text{arithmetic mean}, \]

with equality only when Precision = Recall. The harmonic mean is therefore the most conservative of the three: it stays low unless both inputs are reasonably high, which is exactly the behaviour you want from a single summary number.

Three worked confusion matrices

1 · balanced. \(TP=50\), \(FN=10\), \(FP=10\), \(TN=50\):

\[ \text{Accuracy} = \tfrac{100}{120} = 0.833, \quad P = \tfrac{50}{60} = 0.833, \quad R = \tfrac{50}{60} = 0.833, \quad F_1 = 0.833 \]

With precision and recall equal, all four metrics agree.

2 · high precision, low recall. \(TP=10\), \(FN=40\), \(FP=2\), \(TN=48\):

\[ \text{Accuracy} = 0.58, \quad P = \tfrac{10}{12} = 0.833, \quad R = \tfrac{10}{50} = 0.200, \quad F_1 = 0.323 \]

The model is right when it speaks, but it misses 80% of the positives. Precision alone would have looked excellent — this is the danger of quoting one number.

3 · high recall, low precision. \(TP=45\), \(FN=5\), \(FP=40\), \(TN=10\):

\[ \text{Accuracy} = 0.55, \quad P = \tfrac{45}{85} = 0.529, \quad R = \tfrac{45}{50} = 0.900, \quad F_1 = 0.667 \]

The mirror image: almost every positive is caught, but nearly half the alarms are false. Note that accuracy is lower here than in example 2 while \(F_1\) is twice as high — the two metrics disagree about which model is better, and \(F_1\) is the one paying attention to the positive class.

AUC — the area under it — summarises performance across all thresholds, and equals the probability that a randomly chosen positive is scored above a randomly chosen negative. AUC = 0.5 is random guessing; AUC = 1 is perfect.
  • Precision–recall curve. Precision against recall over the same sweep. Its baseline is the positive-class prevalence, not 0.5.
ROC flatters imbalanced problems

Drop the prevalence slider to 5% and watch: the ROC curve barely changes while the PR curve collapses. The reason is that the false positive rate divides by the number of true negatives, and when negatives are abundant even a large number of false alarms produces a small FPR. Precision divides by the false positives directly and so feels every one of them. On imbalanced data, report the precision–recall curve.

Weighted Fβ

\(F_1\) weights precision and recall equally. When your application does not, generalise it:

\[ F_\beta = \frac{(1+\beta^2)\,(\text{Precision} \cdot \text{Recall})}{\beta^2 \cdot \text{Precision} + \text{Recall}} \]

Setting \(\beta = 1\) recovers \(F_1\). The parameter has a clean interpretation: \(\beta\) is how many times more important recall is than precision. So \(\beta = 2\) weights recall roughly twice as heavily, and \(\beta = 0.5\) weights precision twice as heavily.

Sliding the weight between precision and recall

Fβ as a continuous function of β, with precision and recall as its two asymptotes. Note which direction it moves.

Play
Example · working F₂ through carefully

Take \(TP=45\), \(FN=40\), \(FP=5\), \(TN=10\). First the components:

\[ P = \frac{45}{45+5} = \frac{45}{50} = 0.900, \qquad R = \frac{45}{45+40} = \frac{45}{85} \approx 0.529 \] \[ F_1 = \frac{2(0.900)(0.529)}{0.900 + 0.529} = \frac{0.953}{1.429} \approx 0.667 \]

Now with \(\beta = 2\), so \(\beta^2 = 4\):

\[ F_2 = \frac{(1 + 4)(0.900)(0.529)}{4(0.900) + 0.529} = \frac{5 \times 0.4765}{3.600 + 0.529} = \frac{2.382}{4.129} \approx 0.577 \]
The direction is the point

\(F_2 = 0.577\) is lower than \(F_1 = 0.667\), and it must be. Raising \(\beta\) shifts weight onto recall, and here recall (0.529) is the weaker of the two numbers — so leaning on it drags the score down. If you ever compute an \(F_2\) above your \(F_1\) when recall is the smaller value, you have swapped precision and recall somewhere. This example is the corrected version of one that appeared in the original notes; see the errata.

Choosing \(\beta\) is a statement about relative cost. Cancer screening uses \(\beta > 1\), because a missed tumour is far worse than an unnecessary follow-up scan. A spam filter uses \(\beta < 1\), because a lost job offer is far worse than a spam message reaching the inbox.

Regression metrics

Definition

Mean squared error.

\[ \text{MSE} = \frac{1}{N}\sum_{i=1}^N (y_i - \hat{y}_i)^2 \]

Mean absolute error.

\[ \text{MAE} = \frac{1}{N}\sum_{i=1}^N |y_i - \hat{y}_i| \]

Root mean squared error, \(\text{RMSE} = \sqrt{\text{MSE}}\), returns the result to the original units — which makes it far easier to interpret and to compare against MAE.

Squared error, drawn as an actual square

Drag one prediction away from its target. The shaded area is the squared error — double the gap and the area quadruples.

Play

Mean squared error

  • Advantages. Strongly penalises large errors, which is right when big deviations are disproportionately costly. Smooth and differentiable everywhere, which makes it convenient for gradient-based optimisation.
  • Limitations. Highly sensitive to outliers — a single large error can dominate the total. Its units are squared (predicting house prices in dirhams gives an MSE in dirhams²), so the raw number is hard to interpret.
  • When to use. When large errors are genuinely costly, or when you need a smooth objective for optimisation. Minimising MSE estimates the conditional mean.

Mean absolute error

  • Advantages. Robust to outliers, since errors contribute linearly. Directly interpretable: an MAE of 5 dirhams means predictions are off by 5 dirhams on average.
  • Limitations. Less sensitive to large deviations, which may under-penalise serious mistakes. Not differentiable at zero, though sub-gradient methods handle this routinely.
  • When to use. When robustness to outliers matters, or when interpretability in the original units is important. Minimising MAE estimates the conditional median.
Example · what one outlier does

1 · no large errors. \(y = [3, 0.5, 2, 7]\), \(\hat{y} = [2.5, 0, 2, 8]\), so the errors are \([0.5,\, 0.5,\, 0,\, -1]\):

\[ \text{MSE} = \frac{0.25 + 0.25 + 0 + 1}{4} = 0.375, \qquad \text{MAE} = \frac{0.5 + 0.5 + 0 + 1}{4} = 0.5 \]

2 · one outlier added. \(y = [3, 0.5, 2, 7, 100]\), \(\hat{y} = [2.5, 0, 2, 8, 8]\), so one error is 92:

\[ \text{MSE} = \frac{0.25 + 0.25 + 0 + 1 + 8464}{5} = 1693.1, \qquad \text{MAE} = \frac{0.5 + 0.5 + 0 + 1 + 92}{5} = 18.8 \]

One point multiplied the MSE by more than 4500× while the MAE grew about 38×. That single error accounts for 99.98% of the total squared error — MSE has effectively stopped measuring the other four predictions at all.

Do not compare MSE against MAE directly

In the first example MSE (0.375) is smaller than MAE (0.5), which might look like MSE is "performing better". It is not a meaningful comparison — the two are in different units. MSE is smaller here purely because squaring numbers below 1 makes them smaller. If you want a like-for-like comparison, use RMSE: \(\sqrt{0.375} \approx 0.61\), which is now in the same units as the MAE of 0.5, and correctly larger because RMSE always exceeds MAE when errors vary.
